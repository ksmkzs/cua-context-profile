# CUA context profile

[English](README.md)

Codex デスクトップアプリに同梱されている Computer Use（CUA）ランタイムの手前に置く、小さな中継プログラムです。
ランタイムがモデルの文脈に入れる説明文を、必要な分だけに絞ります。OpenAI の製品ではありません。

```
Codex デスクトップアプリ ─┐                     ┌─ 説明文フィルター（このリポジトリ）
                         ├─ MCP ─ cua-proxy ───┤                              ── MCP ─ node_repl（同梱のまま無改変）
Claude Code ─────────────┘  （標準入出力）      └─ filters.d/*.mjs（追加のフィルター。任意）
```

## モデルから見て変わること

- **初回の説明文。** 素のランタイムは最初の呼び出しで、共通の規則・ネイティブアプリ用 API・ブラウザー用 API を
  まとめて出力します。中継は共通部分だけをその場で見せ、ネイティブ用・ブラウザー用の部分は、その機能を
  実際に初めて使った時点で追加します。文面はベンダーの原文そのままで、言い換えは一切しません。
  説明文の後ろに付く確認ポリシーには手を加えません。
- **`await cua.documentation("full" | "native" | "browser")`** で、原文の全体または一部をいつでも出せます。
  `cua.rewriteDocumentation()` もそのまま使え、使用中の部分も一緒に戻ります。
- **ツールの説明。** 起動時にある機能が無効（`CUA_REPL_ENABLED_SURFACES`）なら、`js` ツールの説明から
  その機能だけに関する段落を外します。

macOS・デスクトップアプリ 26.1103 での実測（文字数）:

| | 素のまま | 中継あり |
|---|---|---|
| 最初の呼び出し（説明文＋ポリシー） | 19,915 | 14,243 |
| ネイティブアプリを初めて使うときに追加 | – | 2,189 |
| ブラウザーのタブを初めて使うときに追加 | – | 3,962 |
| `js` ツールの説明（デスクトップアプリのみ有効時） | 3,237 | 1,483 |

## 仕組み

素のランタイムは普通の MCP サーバー（標準入出力）です。中継はすべてのメッセージを1バイトも変えずに通し、
`js`／`js_reset` の `tools/call` と `tools/list` だけを見ます。使うのはランタイムがもともと備えている次の3つだけで、
ベンダーのファイルは複製も変更もしません。

1. 環境変数 `NODE_REPL_JS_BANNER`（公開されている `cua` の入口を包み、機能を初めて使ったときに目印を残す数行）
2. MCP のメッセージそのもの（説明文は通常の結果テキストとして届きます）
3. 公開されている `cua` の JavaScript API

アプリから何も複製せず、特定のビルドにも固定していないので、アプリが更新されても入れ直しは不要です。
中継が認識できないものはそのまま通します。説明文の構成が変われば全文がそのまま表示され、
ランタイム内の部品が動いていなければ説明文には一切手を加えません。

Codex のターン情報を送らないクライアント（Codex アプリ以外）には、接続ごとに1つのセッション識別子を補い、
`turn_ended` もその識別子に読み替えます。

## 前提としていること

現行のデスクトップアプリ（26.1103 で確認）のランタイムは、自分を起動したプログラムに OpenAI の署名があるときだけ
アプリを操作できます。それ以外から起動すると、アプリの一覧は取れても、アプリへの接続で失敗します
（"Sky Computer Use native pipe startup failed"）。そのため中継は、アプリに同梱されている Node の上で動きます。ランタイムの手前に居続けられるのもそのためです。
これは現時点でそう動くというだけで、保証されたものではありません。ベンダーがここを狭めた場合は、対応するまで中継を外す（`CUA_PROXY=off`）必要があります。

## インストール

macOS と Codex デスクトップアプリ（`ChatGPT.app` または `Codex.app`）が必要です。中継はアプリ同梱の Node で動きます。

```sh
sh install.sh codex      # ~/.local/share/cua-proxy に入れ、Codex デスクトップアプリから使う
sh install.sh            # 入れるだけ（Claude Code は claude-cua-mcp が自動で見つけて使います）
sh install.sh uninstall
```

`codex` は、ログイン中のセッションに `CODEX_NODE_REPL_PATH` を設定し、ログインのたびに設定し直す LaunchAgent を
置きます。実行後にデスクトップアプリを終了して開き直してください。

## 設定（環境変数）

| 変数 | 効果 |
|---|---|
| `CUA_PROXY=off` | 起動スクリプトが素のランタイムを直接起動する |
| `CUA_PROXY_DOCS=off` | 説明文フィルターを使わない |
| `CUA_PROXY_TOOLS=js,js_reset,turn_ended` | クライアントに見せるツール |

## フィルター

フィルターは `filters.d/` に置くモジュールで、既定のエクスポートが次のいずれかを持つオブジェクトを返します。
`banner`（ランタイムのバナーに足す JavaScript）、`beforeCall(call)`（`call.meta` を設定でき、ランタイム内では
`nodeRepl.requestMeta['cua-proxy']` で読めます。`{result}` を返すとランタイムを呼ばずに応答します）、
`afterCall(call, result)`、`tools(list)`、`close()`。読み込みに失敗したフィルターは飛ばします。
[safari-window-mcp](https://github.com/ksmkzs/safari-window-mcp) はこの仕組みで、セッションごとに専用の Safari
ウィンドウを与えます。

## デスクトップアプリが更新されたら

中継はアプリが渡す環境だけで動くので、入れ直しは要りません。ただし、更新より前に起動したランタイムは新しい版の Computer Use サービスに届かなくなり、アプリの操作が "Sky Computer Use native pipe startup failed" で失敗します。中継は、ランタイムのファイルが起動後に入れ替わっているときだけ、このエラーに「アプリが更新された。MCP サーバーをつなぎ直すか新しいセッションを始める」という案内を付け足します。説明文の区切りが新しい版でも認識されるかは、[claude-cua-mcp](https://github.com/ksmkzs/claude-cua-mcp) の `sh check.sh` で確かめられます（26.1111 で確認済み）。

## テスト

```sh
npm test                                   # Node 22 以上。アプリが入っていれば実物の説明文での確認も含む
python3 -m unittest discover -s tests      # 更新の監視
```

定期実行のワークフローがデスクトップアプリの公開リリース情報を監視し、新しいビルドが出ると Draft PR を作ります。
これは「そのビルドを入れた Mac で `npm test` を実行する」ための通知であり、互換性を保証するものではありません。

## 制約

確認済みなのは macOS のみです。以前の Windows 用ランチャーはこの版には含めていません。
